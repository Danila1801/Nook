# Nook — honest audit

**Date:** 2026-08-05 · **Branch:** main · **Build:** passing (238ms, 105.7 kB gzip)

---

## Verdict

Not done. But the problem is not the one you think it is.

The taste in this project is good. `tokens.css` is a considered piece of work —
a warm neutral ramp, accents deliberately held at low saturation, a dark theme
that is not an inversion, contrast ratios written into the comments, safe-area
values centralised so the `BottomNav` double-count bug can't recur. The `Orb` is
a real component: halo, drift blobs, baked grain, a rim light on a 58s rotation,
everything on `transform`/`opacity`, with a hand-composed still frame for
`prefers-reduced-motion`. Somebody thought hard here.

**The design system exists and the screens don't use it.** That is the whole
diagnosis. Everything below is downstream of it.

## 1. The reason it looks boring

Measured across all 20 stylesheets in `src/screens/` and `src/components/`:

| What | Count |
|---|---|
| Raw `px` values (excluding `0px`/`1px`) | **301** |
| `var(--space-*)` uses | 14 |
| `var(--text-*)` uses | **2** |
| `var(--radius-*)` uses | 2 |
| `var(--dur-*)` uses | 5 |
| Raw transition durations (`0.3s`, `0.5s`…) | 36 |
| `font-family` declarations | 101 |
| …of which use `var(--font-*)` | **101** |

Read the last two rows against the third. Every screen uses the right
*typefaces* and almost none of them use the *type scale*. `tokens.css` defines
an eight-step scale from 11px to 48px; the app references it twice. Instead,
[RitualBreath.css](../src/screens/RitualBreath.css) hand-types `40px`, `32px`,
`11px`, `letter-spacing: -0.5px`, `margin-top: 56px / 18px / 12px`. Every other
screen does the same, independently, with different numbers.

The consequence is not that any single screen is bad. It's that no two screens
share a proportion. There is no vertical rhythm to fall into, no repeated
interval, no size relationship that recurs and becomes the app's voice. That
reads to the eye as *cheap* long before it reads as *wrong* — and it's the
exact texture people mean by "generic."

**This is the highest-leverage fix in the repo and it's mechanical.** Migrating
301 raw values onto the existing scale is an afternoon, requires no new design
decisions, and changes how the entire app feels.

### 1b. Two of five ritual players were never designed

| Player | Visual layer | Controls |
|---|---|---|
| Breath (9 rituals) | `Orb` @ 280px, scales with the breath phase | close only |
| Eyes (5) | `Orb` @ 220px | close only |
| Stretch (14) | `Figure` illustrations, all 8 keys covered | pause + skip |
| **Movement (9)** | **none** | pause + skip |
| **Mind (8)** | **none** | close only |

[RitualMind.jsx](../src/screens/RitualMind.jsx) renders an eyebrow, one line of
instruction text, and `5:00` counting down. That's the entire screen, for up to
ten minutes. [RitualMovement.jsx](../src/screens/RitualMovement.jsx) is the same
plus a step counter.

**17 of 45 rituals — 38% of the catalogue — are a paragraph and a number.** Not
a missing asset. A missing decision.

### 1c. The breath orb has two heartbeats

[RitualBreath.css:40](../src/screens/RitualBreath.css#L40) scales the orb on the
guided phase duration (4s, 7s, 8s). Meanwhile
[Orb.css:117](../src/components/Orb.css#L117) runs `orb-body-breathe` on its own
independent 12s loop, and `orb-halo-breathe` on a 9s loop. During a 4-7-8
exercise the user is watching three unrelated breathing rhythms at once.

The ambient loops are lovely on `Welcome` and `Today`, where the orb is idle.
Inside the breath player they should stop and let the guided pattern own the
motion. `Orb` already has a `paused` prop — this is a small change with a large
perceptual payoff.

### 1d. Pure white in a warm palette

13 occurrences of `#ffffff` across 12 files, all on terracotta buttons, plus
raw `rgba(255,255,255,…)` in the ritual canvases. `--ink-invert` exists for
exactly this and resolves to `#FBF7EF` — warm. Cold white on warm terracotta is
a small note played wrong, repeated on every primary button in the app.

## 2. The app claims things it doesn't do

### Offline is not implemented
[public/sw.js](../public/sw.js) declares `CACHE_NAME = 'nook-v1'` and never
references it again. No `fetch` handler, no `cache.addAll`. The file only
handles `notificationclick` and `push`. The README and manifest present Nook as
an offline PWA; in airplane mode it is a white screen.

### …and the typography is network-dependent anyway
[index.html:28](../index.html#L28) loads Instrument Serif, Inter and JetBrains
Mono from Google Fonts with `display=swap`. Even once caching is fixed, the
display serif that carries the app's identity is a third-party request. On the
target device — a phone in a building with bad signal — Nook falls back to
Georgia. Self-host the three families; it also removes a tracking vector from an
app whose pitch is that it has no backend.

### Notifications only fire with a tab open
`setTimeout`-based scheduling. For a product whose core loop is "we tap you on
the shoulder every 90 minutes," this is the feature, and it doesn't work when
the app is closed — which is always.

### `nl.js` / `ro.js` are 22-byte stubs
`export const x = {}`. Silent English fallback. (Credit where due: **en and ru
are at exact parity, 429/429 keys**, and no hardcoded strings leak into JSX.
The i18n discipline is real.)

## 3. Defects

**Correctness**

1. [RitualMovement.jsx:39-52](../src/screens/RitualMovement.jsx#L39-L52) calls
   `setStepIndex` and `setIsComplete` *inside* the `setElapsedInStep` updater.
   State updaters must be pure — React StrictMode double-invokes them in dev,
   which can double-advance the step.
2. Breath, Eyes and Mind have **no pause control**. A 5-minute breath ritual and
   a 10-minute mind ritual can only be abandoned, not paused. Stretch and
   Movement both have one. Inconsistent, and the two longest players are the
   ones missing it.
3. [Today.jsx:190-222](../src/screens/Today.jsx#L190-L222) renders the day's
   pauses as non-interactive `<li>`. Only the "up next" card is tappable — you
   cannot start the 15:00 stretch at 14:00 from the home screen.
4. 4 lint errors: [i18n/index.js:50](../src/lib/i18n/index.js#L50),
   [rhythm/engine.js:144](../src/lib/rhythm/engine.js#L144), plus 2 more; 3
   `react-hooks/exhaustive-deps` warnings in `Progress.jsx`.

**Accessibility**

5. **Zero `aria-live` regions in the entire app.** Breath phase changes,
   countdowns, step advances and completions are all silent to a screen reader.
   The core interaction is invisible to assistive tech.
6. [Rhythm.css:189](../src/screens/Rhythm.css#L189) slider thumb is 20×20px
   against a documented 44×44 minimum — and it's in onboarding.

**Convention violations (against CLAUDE.md)**

7. Four `transition`s on `width`/`height` — layout thrash on every frame, when
   the rule is transform/opacity only:
   [Progress.css:76](../src/screens/Progress.css#L76),
   [RitualStretch.css:74](../src/screens/RitualStretch.css#L74),
   [RitualCanvas.css:99](../src/components/RitualCanvas.css#L99) and `:149`.
8. `window.alert()` at [You.jsx:84](../src/screens/You.jsx#L84). A native modal
   in an app whose one rule is that it's quiet.
9. Raw `rgba()` colours in 10 places, on top of the 13 `#ffffff`.

**Repo hygiene**

10. 51 files modified, +1934/−267 uncommitted. All of the above is being
    audited against a working tree, not a commit.

## What's actually good

Worth naming, because the instinct to burn it down would be wrong:

- `tokens.css` — genuinely well-reasoned, including the comments explaining
  rejected options
- `Orb` — the best component in the app; the `Orb.variants.md` rationale for
  *removing* the sphere-shading gradient is the kind of judgement that can't be
  faked
- `BottomNav` — safe-area handling correct, active state carries a non-colour
  signal (WCAG 1.4.1)
- No `100vh` anywhere. `100dvh` discipline held.
- en/ru at exact key parity; no string literals in JSX
- Zero gamification. The one rule is intact everywhere — including the About
  copy, which says so out loud.
- The debug **ADD SAMPLE DATA** button is gone (CLAUDE.md is stale on this)

---

## Recommended order

1. **Migrate the screens onto the type and space scale.** Mechanical, no new
   decisions, biggest single change to how the app feels.
2. **Design the movement and mind players.** 38% of the catalogue currently has
   no visual layer.
3. Pause the ambient orb loops inside the breath player.
4. Implement the service worker cache; self-host the three font families.
5. Add pause to breath/eyes/mind; make the Today list tappable.
6. `aria-live` on the ritual players; fix the slider target.
7. Lint, raw colours, `width` transitions, `window.alert`.
8. Then decide about `nl`/`ro` and background notifications — both are scope
   questions, not defects.
